# 🚀 KubeApp - Kubernetes GitOps CI/CD Pipeline

A containerized web application deployed on **Kubernetes using Docker, Docker Hub, GitHub Actions, ArgoCD, K3s, and AWS EC2**.

The project demonstrates an end-to-end **GitOps-based CI/CD workflow** where code changes trigger a GitHub Actions pipeline, Docker images are built and pushed to Docker Hub, Kubernetes manifests are updated, and ArgoCD automatically deploys the changes to the Kubernetes cluster.

---

# 📌 Project Overview

This project implements an automated CI/CD and GitOps deployment pipeline for a frontend and backend application.

The workflow uses:

- GitHub for source code and GitOps repository
- GitHub Actions for CI automation
- Docker for containerization
- Docker Hub for image storage
- Kubernetes/K3s for container orchestration
- ArgoCD for Continuous Deployment
- AWS EC2 for hosting the Kubernetes cluster

# ⚙️ GitHub Actions CI Pipeline

GitHub Actions automatically builds the frontend Docker image, pushes the image to Docker Hub, and updates the Kubernetes deployment manifest with the latest image tag.

### CI Pipeline Steps

1. Checkout source code
2. Login to Docker Hub
3. Build Docker image
4. Push Docker image to Docker Hub
5. Update Kubernetes image tag
6. Commit updated Kubernetes manifest
7. Push the manifest change to GitHub

# 🐙 ArgoCD Continuous Deployment

ArgoCD is used to implement **Continuous Deployment using the GitOps approach**.

ArgoCD continuously monitors the Kubernetes manifests stored in the GitHub GitOps repository.

When GitHub Actions updates the Kubernetes deployment manifest, ArgoCD detects the change and automatically synchronizes the desired state with the K3s Kubernetes cluster.

# 🔁 GitOps in Action

This is the core of the project.

Every change to the frontend automatically flows through the CI/CD pipeline.

### Deployment Flow

```text
1. Developer modifies frontend code
              ↓
2. Git push to main
              ↓
3. GitHub Actions starts
              ↓
4. Docker image is built
              ↓
5. Image pushed to Docker Hub
              ↓
6. Kubernetes manifest updated
              ↓
7. GitOps repository receives the change
              ↓
8. ArgoCD detects the change
              ↓
9. ArgoCD synchronizes Kubernetes
              ↓
10. New frontend pod is deployed
              ↓
11. Updated website becomes live
```

### How to Update the Application

Edit any file inside the `/frontend` folder.

For example, modify:

```text
frontend/home.html
```

Then run:

```bash
git add .
git commit -m "update: changed homepage heading"
git push
```

GitHub Actions will automatically:

1. Build a new Docker image
2. Push the image to Docker Hub
3. Update the image tag in `k8s/frontend-deployment.yaml`
4. Commit the updated manifest
5. Push the change to GitHub

ArgoCD will then:

1. Detect the Git change
2. Synchronize the application
3. Deploy the new image to Kubernetes
4. Replace the old frontend pod

Finally, refresh the website to see the change.

# 🔐 GitHub Secrets Configuration

The GitHub Actions workflow uses GitHub Secrets to securely authenticate with Docker Hub.

Navigate to:

```text
GitHub Repository
      ↓
Settings
      ↓
Secrets and variables
      ↓
Actions
      ↓
New repository secret
```

Add the following secrets:

| Secret Name | Value | Purpose |
|---|---|---|
| `DOCKERHUB_USERNAME` | `refa642` | Docker Hub username |
| `DOCKERHUB_TOKEN` | `<Docker Hub access token>` | Authenticate with Docker Hub |

### Docker Hub Access Token

Create a Docker Hub Personal Access Token and store it as:

```text
DOCKERHUB_TOKEN
```

**Never place the Docker Hub access token directly inside the workflow file or README.**
